# Jef V1.9 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a tested V1.9 `com.nthn` agent with real research, richer memory, durable bounded tasks, system tools, and an honest self-development/update path.

**Architecture:** Extend the existing Node agent registry and mobile CLI in focused modules. Retain Android's native package boundary and explicit approval path. Store durable state under app-private `.local/agent`.

**Tech Stack:** Node 24 TypeScript, built-in SQLite, Android Java/WebView, node:test, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-11-jef-v1.9-design.md`

## Global Constraints

- App version is `apps/nthn/VERSION`; the target is `1.9`.
- Keep V1.8 provider, chat, workspace, file edit, memory, and approval compatibility.
- No hardcoded credentials, fake tool output, silent Android install, or unbounded network access.
- Do not modify bootstrap or unrelated Android infrastructure.

## Review Focus

- Redirects to loopback/private addresses must be rejected by web retrieval.
- Search errors must be reported as errors, never invented citations.
- Existing memory JSON must migrate without losing records or scope.
- A resumed task must not execute a stale approval or duplicate a mutation.
- A source edit must not be reported as a running-app update.

**Files:** Create `server/agent/research.ts`; modify `server/agent/tools.ts`, `server/agent/nthn-agent-cli.ts`; test `tests/jef-research.test.ts`.

**Interfaces:** `ResearchService.search(query, signal)` returns source records; `ResearchService.open(url, signal)` returns extracted text with final URL and title. The tool registry exposes `web_search` and `open_url` only when configured.

- [ ] Write tests for URL validation, redirect handling, extraction, search provider responses, citations, and tool execution; run red.
