# Jef V2 Implementation Plan

**Goal:** Deliver a verifiable V2 `com.nthn` APK that gives Jef broad control of NTHN's own Linux and Android app environment, reliable provider access, and an owner-controlled GitHub update path.

**Architecture:** Keep the existing Termux-derived terminal, Node agent, provider vault, task store, and installer. Extend the Node agent with strict model and GitHub services, and connect Android-only capabilities through explicit native bridge methods. Keep each permission visible in the UI and each external action auditable.

**Tech stack:** Android Java, Node 24 TypeScript, SQLite, GitHub REST API, existing GitHub Actions build workflow.

## Work packages

- [ ] Repair provider chat: exclude incomplete turns, expose safe HTTP status and request-shape failures, verify live chat on the device, and confirm Terminal symptoms separately.
- [ ] Model control: make free-only the default, reject paid and unknown-price routes, allow manual selection of an exact free route, expose provider quota observations where available, and report unknown limits honestly.
- [ ] Provider setup: accept a key through the private native input, suggest its provider, test a real Jef-shaped chat request, discover compatible models, and keep secrets out of output and logs.
- [ ] NTHN Linux access: expose app-private home and compatible prefix via the real process and file tools; add a native, bounded bridge for live terminal session inspection/control; verify command output and cancellation on device.
- [ ] Android awareness: expose current NTHN screen and app state, camera capture, foreground location, user-selected shared files, speech input, and spoken replies through Android permission-gated native services. Keep capture and listening visible and stoppable.
- [x] Core identity: keep Jef's strategic, independent, witty and darkly comic personality consistent across providers and conversations through one shared prompt module. Inject actual runtime state separately, suppress humor for serious contexts, and connect changing ecosystem knowledge to research rather than static claims.
- [ ] Source development: inspect/edit approved NTHN source, run tests, track diffs, and produce a build manifest. Do not claim local Android builds when the toolchain is unavailable.
- [ ] GitHub delivery: save a separate least-privilege encrypted write token, prepare a reviewable branch/commit, push after owner approval, dispatch the existing NTHN workflow, poll status, and download/verify the signed release APK.
- [ ] Release: bump `apps/nthn/VERSION` to `2`, run Node/Android verification and the GitHub workflow, verify signing/package/version, and test install and rollback paths on the device.

## Constraints

- The NTHN app UID cannot modify the Android kernel, other apps' private data, or the OS outside its permissions.
- Camera, microphone, location, and shared-storage access require Android permission or picker flows; whole-screen capture needs a separate MediaProjection consent flow.
- API keys, GitHub write credentials, and signing material are never hardcoded or included in model context.
- Free-model pricing and quotas are provider observations, not guarantees of continued availability.
- Pushing, workflow dispatch, and APK installation are explicit owner-approved actions.
